# RoverSense

**ML anomaly detection for rover sensor telemetry — trained in Python, running live in your browser.**

On a field rover, a fouled pH probe or a drifting gas sensor fails *silently*: the numbers keep flowing, they just stop meaning anything. RoverSense learns what nominal telemetry looks like across six sensor channels, then flags and classifies sensor faults in real time.

**Live demo:** https://qasimjethwa.github.io/roversense/ — inject faults into a live simulated rover and watch the detector catch them. No backend; the model runs 100% client-side.

## How it works

1. **Train (Python).** `train.py` simulates nominal rover telemetry (battery, motor current, chassis temp, pH, soil moisture, gas — 1 Hz, drive cycles, thermal coupling) and trains a scikit-learn `IsolationForest` (64 trees, 18 context features per sample: level deviation, stillness, transient delta). A deterministic guardrail layer (robust-z, stuck-value, transient, dropout) is calibrated from the same training stats.
2. **Export every tree.** All 64 trees — splits, thresholds, leaves — are serialized to `docs/model.json` (622 KB), with the guardrail stats beside them.
3. **Run anywhere.** `docs/forest.js` re-implements the exact scikit-learn scoring path in dependency-free JavaScript. Verified bit-identical: max |JS − sklearn| = **1.1e-16** over 400 test samples. The same detection logic (EWMA smoothing, dwell, hysteresis) runs in `train.py`, `detector.py`, and the browser — incident spans match sample-for-sample.

## Measured performance

Evaluated on a labeled 30-minute stream with 5 injected fault/anomaly episodes (threshold calibrated for ~1% false-positive rate on held-out nominal data; **zero** false incidents on a 20-min validation stream):

| Metric | Value |
|---|---|
| Precision / Recall / F1 | 0.986 / 0.755 / 0.855 |
| ROC-AUC | 0.858 |

| Episode | Detected in | Via |
|---|---|---|
| pH probe freeze (stuck value) | 21 s | stuck-value guardrail |
| Gas sensor drift (slow bias) | 7 s | robust-z guardrail |
| EMI spikes (motor-current transients) | 17 s | transient guardrail |
| Soil-moisture dropout (90 s NaN gap) | 0 s | dropout guardrail |
| **Gas leak (real event, not a fault)** | **3 s** | robust-z guardrail |

## Quickstart

```bash
pip install -r requirements.txt

# Retrain the model, re-evaluate, re-export docs/model.json + docs/metrics.json
python train.py

# Score a CSV of telemetry (header: battery_v,motor_current,chassis_temp,ph,soil_moisture,gas_mq)
python detector.py telemetry.csv -o scored.csv

# 60 s self-test on simulated data
python detector.py --demo
```

Serve the demo locally with anything static, e.g. `python -m http.server -d docs 8000`.

```
brag-output/        launch video deliverables
```

## Why this architecture

Point-wise anomaly detectors can't see "stuck" or "drifting" — a frozen sensor reading looks perfectly nominal one sample at a time. The 18 features give each sample its recent context (stillness over a trailing window, deviation from the training median, transient deltas), and the guardrail layer covers the known failure modes deterministically. ML for the subtle stuff, physics for the obvious stuff — the way real telemetry monitoring works.
